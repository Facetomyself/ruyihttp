# Gecko release policy for the standalone POSIX HTTP/3 client

The build pin stays at Firefox 161.0 (`9c70d5d48c866afc2e581d6b7ff6de98a1371d99`), Neqo 0.34.0 (`e302b43503f44e09f4257573dd320621516d1560`), NSS 3.133 and NSPR 4.40. This change is confined to connection parameters supplied to Neqo by the donor POSIX client and the internal Python profile map. The Windows donor and its JSON profile are unchanged.

## Donor behavior and client scope

* Linux v0.9.2 used `.webtransport(wt).connect(wt)`. Ordinary requests had `wt=false`, so Extended CONNECT setting id `0x08` was absent. Its two windows were already correct; its default eligible-version order when `version2=true` was also correct. This was confirmed over real loopback H3 for 159, 160 and 161 on Linux AArch64.
* The v0.9.2 macOS donor used generic Neqo 2/1 MiB windows, left Extended CONNECT off for ordinary requests, ordered v1 ahead of v2 when the profile enabled version negotiation, and inherited both versions when it was explicitly disabled. It selected an eight-byte source connection ID. Gecko's socket glue selects three bytes throughout 100–161. Independent [official Firefox 161 captures on both native macOS targets](https://github.com/Facetomyself/ruyihttp/actions/runs/45766325962) confirm three bytes in the first client Initial, a 1252-byte UDP datagram, both Gecko windows, v2 negotiated after a v1 Initial, and id `0x08=1`. The macOS patch now uses the same connection-ID generator width as Gecko; it does not rewrite packets.
* The first SCID-corrected Apple Silicon [strict replay](https://github.com/Facetomyself/ruyihttp/actions/runs/45769818547) isolated a missing H3 ClientHello extension `34` and a 23-byte normalized Initial difference at 159–161. [Gecko PSM](https://github.com/mozilla-firefox/firefox/blob/9c70d5d48c866afc2e581d6b7ff6de98a1371d99/security/manager/ssl/nsNSSComponent.cpp#L858-L860) sets the delegated-credentials NSS default. The enabled preference is in `all.js` for 100–101 and `StaticPrefList.yaml` for 102–161. Linux already sets the real NSS option on its QUIC descriptor. The macOS patch enables the same `SSL_ENABLE_DELEGATED_CREDENTIALS` on its own new QUIC connection before the handshake, leaving NSS process defaults and native TLS verification unchanged. NSS encodes the extension and negotiates the capability; packet padding and the extension-permutation algorithm stay unchanged.
* The new POSIX profile passes `h3_connect`, `max_data`, and `max_stream_data_bidi_local` explicitly. The existing `version2` flag selects the real pinned Neqo preference list (v2 then v1), while the initial version stays v1. With a v1-only peer Neqo completes v1; a locally v1-only client offers no v2 to a dual-version peer. No wire bytes are rewritten to mimic these settings.
* This is a client-side HTTP/3 connection setting, not a generic tunnel API. Neqo encodes the setting and continues enforcing peer negotiation. The existing WebTransport entry remains separate and off for ordinary requests; the zero-valued WT setting is not an enabled capability. Requests `fetch` still rejects method `CONNECT`, and the native JSON interface has no generic `connect` or `connect-udp` operation. A pre-existing explicitly configured WebTransport connection still enables the CONNECT prerequisite. Tests drive genuine peers with and without id `0x08`, verify the real GET completes, and verify the ordinary request bridge opens neither a tunnel nor WebTransport. They do not claim a bidirectional tunnel API.

## Ordered source qualification

`tools/posix_firefox161.py` lists the per-slot source patches in apply order. The new donor policy patch is last after the ABI/TLS/runtime patches and verified against the same donor commit. The source workflow verifies exact Gecko glue, preference, and caller digests, architecture, dependency closure and deployed library symbols. `ci/smoke_posix_quic_policy.py` adds loopback version, SETTINGS and receive-limit checks, including absent CONNECT preference, reversed profile key order, independent window values, and malformed preference values. The existing full H1/H2/H3, body ABI/thread, fallback and in-place upgrade witnesses remain required on CPython 3.10 and 3.14. The promotion tool also recomputes the strict official Firefox comparison for the three version receipts from each interpreter using the current exact-slot fixture. This file describes behavior and proof requirements; the platform provenance records the actual qualified artifacts.
