# 05 · 原生构建、准入与发布

[架构总览](README.md) · [交互工作流](diagrams/native-delivery.html) · [可编辑图源](diagrams/native-delivery.json)

**先验证原生库，再打包，最后验证准备交付的那个 wheel。** 编译产生的库进 `native/<slot>/` 前需要候选回执；`pip wheel` 只从已选槽复制成品库；最终验收针对重新打包后的 wheel，而非候选包、源码树或一次 `dlopen`。`Wheels` 的终点是 Actions 产物；发布维护者另行核对摘要和回执、发布到 GitHub Release。此工作流没有 PyPI 或 GitHub Release 发布步骤。

## 1. 打包只消费一个平台槽

- [项目元数据与 package-data](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/pyproject.toml#L1-L23) 声明 `setuptools.build_meta`、Python ≥ 3.10、依赖与版本；[extras 和文件模式](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/pyproject.toml#L40-L49) 包括 `masque`、`socks`、原生扩展名与数据。源码发行包用 [MANIFEST.in](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/MANIFEST.in#L1-L23) 带上各现有 bank、补丁、工具与测试；这与 wheel 只选一槽是两个清单。
- [setup.py 平台选择](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/setup.py#L18-L60) 优先使用白名单 `RUYIHTTP_PLATFORM`，否则用 OS 和机器架构（`RUYIHTTP_MACHINE` 可覆盖探测）。覆盖只选槽、并非交叉编译；Linux 低基线打包还要求实际原生架构及 glibc ≥ 2.31。`build-required`、缺库、混槽、额外库或摘要变动都会让打包停下。`BundleNative` 清除构建输出里旧 `.dll/.dylib/.so`、复制该槽，在 wheel 内生成 `ruyihttp/native-provenance.json`（原样复制槽的 `provenance.json`，原生摘要须与 manifest 一致），并校验四项数据的 SHA-256。`PlatformWheel` 标记 `Root-Is-Purelib: false`，标签是 `py3-none-<platform>`：没有 CPython 扩展 ABI 并不等于纯 Python 或跨平台。[复制与标签代码](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/setup.py#L98-L180) · [Linux 标签守卫](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/setup.py#L63-L95)。

## 2. POSIX 编译：源码身份、补丁、装载闭包

1. [原生候选工作流](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/.github/workflows/native-arm64-intel.yml#L63-L102) 检查 CPU、macOS 禁用 Rosetta，`verify` 守已提交槽，`rebuild` 从源码构造候选，`requalify` 取指定 run/attempt 的产物来复验，`baseline` 指定原生 Linux Bullseye 低基线。源码路径先检出 `cutetailbud/ff-ruyijs` 的 [`f557fcd437aae5f18f313eb330bd3ef50f5fc7df`](https://github.com/cutetailbud/ff-ruyijs/commit/f557fcd437aae5f18f313eb330bd3ef50f5fc7df)，验证供体原来的 Firefox 160 gitlink `2887d9de1f69c0e9776413da80e7ba0d1225dd9b`，然后**另行**检出 `FIREFOX_161_0_RELEASE` 的 [`9c70d5d48c866afc2e581d6b7ff6de98a1371d99`](https://github.com/mozilla-firefox/firefox/commit/9c70d5d48c866afc2e581d6b7ff6de98a1371d99)。验证 NSS tag `NSS_3_133_RTM`、NSS/NSPR 头文件、Mozilla `Cargo.lock`、vendored Neqo commit `e302b43503f44e09f4257573dd320621516d1560` 与 `nss-rs` 0.16.2 commit `bb8ed19e82679e613a636f530d15ddc823f1b040`，以及 Gecko H3 三个文件的内容摘要。独立桥接 Cargo lock 要使用该本地 vendor overlay，并在编译后再次核对。这里编译的是供体适配层和选定 Firefox 组件，产物不是完整 Firefox。[检出与校验](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/.github/workflows/native-arm64-intel.yml#L144-L218) · [源校验实现](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/tools/posix_firefox161.py#L81-L141)。

[补丁顺序](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/tools/posix_firefox161.py#L44-L78) 是候选身份的一部分；脚本先输出每片 SHA-256，逐片 `git apply --whitespace=error --check` 后再应用。**Linux**：`h3-body-abi-v1.patch` → `firefox161-linux.patch` → `firefox-posix-quic-policy-linux.patch`。**macOS**：`macos-necko-quic-tls-info.patch` → `h3-body-abi-v1.patch` → `macos-h3-global-handles.patch` → `firefox161-macos.patch` → `firefox-posix-quic-policy-macos.patch`。策略补丁向独立 Neqo 传 Extended CONNECT、v1 起步而后允许按配置协商 v2、两个接收窗口；macOS 还在 QUIC 描述符上启用 delegated credentials、使用三字节 SCID。是输入/连接行为改变，不是在观察端改包；普通 H3 请求的 Extended CONNECT 设置不是可公开调用的隧道 API，MASQUE 外层是另一条实现。[应用脚本](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/build_native_target.sh#L8-L17) · [适配的范围与差异](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/native/patches/GECKO_H3_POLICY.md#L17-L27)。

## 3. 运行时 ABI：版本见证与能力协商分开

- **Core / TLS**：`_transport._load_library()` 默认加载包内 sibling `necko_core`，支持显式 `library_path` 或 `NECKO_CORE_LIBRARY`；Windows 用同目录 loader 辅助。`ctypes` 声明 `necko_socket_*` / `necko_exchange_*` 的入参、返回码和输出位置；`_nss.configure_library` 同样声明 `necko_tls_*`，包括定制 TLS profile、读写、证书验证/解码回调及 ALPN/版本/cipher，并对当前槽强制比较 `necko_tls_nss_version()`。`smoke_native_target` 额外检查 NSPR、可声明的 `core_abi_version`（Windows 为 1）与实际映射路径；macOS 查 dyld，Linux 查 `/proc/self/maps`，Windows 查模块句柄路径。不能用文件存在或 DLL 可加载代替实际事务。[core loader / ctypes](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_transport.py#L135-L247) · [TLS 签名与 NSS 守卫](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_nss.py#L111-L177) · [本机核验](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/smoke_native_target.py#L156-L251)。
- **QUIC 控制面 / 数据面**：`_http3.Connection` 默认打开 core 旁的 `necko_quic`（`NECKO_QUIC_LIBRARY` 可覆盖）；`necko_quic_call(u64 handle, char*, size_t) → char*` 接 JSON 控制帧，`necko_quic_set_decoder` 注册解码回调。验收用 manifest 的 `h3_version_export` 按正确返回类型调用 `necko_quic_version`：Windows 和 macOS 是 C 字符串 `neqo-0.34.0/nss-3.133`，Linux 是 `u32` 值 `32`；它不是运行时 body ABI 版本。数据面只在 `necko_quic_body_abi_version()` 返回 `1` **且** `read_v1`、`write_v1` 同时存在时采用二进制。两端校验 `1..65536` 字节、QUIC stream varint 范围、有效输出计数与 FIN；指针存储由调用方保活，原生端不持有缓冲区，线程局部错误字符串仅在同一线程的下一次正文错误前有效，句柄只能由连接拥有线程使用。缺失导出或版本不合时采用 JSON/Base64；Windows 当前明确三项导出都无，POSIX 必须实际通过二进制与强制 JSON 对照。只有正文走新数据面，控制帧仍为 JSON。[Python 协商](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_http3.py#L29-L88) · [控制绑定](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_http3.py#L133-L215) · [数据路径](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_http3.py#L347-L395) · [原生体 ABI](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/native/patches/h3-body-abi-v1.patch#L53-L141)。
- **Windows H3 的 `Response.tls`** 是桥 `info.tls` 的历史形状：`backend: "NSS/Neqo"`、`alpn: "h3"`、TLS `version`、`cipher_suite`、`resumed`，不补填 `nss` 或 `profile`。NSS 版本另由 core 导出实测；H3 JSON 中看见 `version` 也不能当 NSS 总版本。POSIX 的 H3 测得 `backend: "NSS"`，另有 `nss` 与 `profile` 字段。字段少不是 TLS 关闭；与浏览器比的是线路字段，而非 Python 遥测字段名称。[读取原生 TLS 信息](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/_http3.py#L284-L300) · [平台 H3 见证](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/smoke_native_target.py#L114-L131) · [Windows／POSIX 字段说明](../platform-support.md#094-qualification-policy)。

## 4. 三层验收：预检、候选准入、最终 wheel

| 层级 | 执行者与验收材料 | 通过后发生什么 |
| --- | --- | --- |
| 候选预检 | `stage_native_candidate.py` 要目标本机、空的 `build-required` 槽、准确供体/Firefox/补丁顺序、全部库、架构与依赖/部署测量。Linux 低基线预检扫描 version **needs**、导出、`DT_NEEDED`、`RUNPATH`、链接闭包和系统提供者；`auditwheel show` 验候选标签，并非用 `repair` 改标。 | 暂存 disposable checkout，`ready` 仅允许候选打包；版本戳 `0.9.4.dev<run>+gha.<attempt>`。`source-native-wheel-*` 或诊断包不是可发布成品。 |
| 机器回执 → 原生 bank | `native-arm64-intel.yml` 上现代 CPython 3.10/3.14 的实装 H1/H2/H3、IPv4/IPv6、正文 ABI/owner、QUIC 策略、升级和同槽 Firefox 判断通过；`promote_native_candidate.py` 核对 run/attempt/job/commit、源与锁、wheel SHA-256、逐文件字节、机器可读 wire JSONL。低基线另要 `linux-minimum.yml` 原始 ZIP 与各 endpoint `summary.json`：重核 API 摘要、生产 wheel 身份、glibc 并用同参考重算 wire；另关联现代旧版升级通过的作业。若是 `requalify`，源候选和重打包后的 wheel SHA 可不同；二者的 native 字节清单必须一致。 | `--check-only` 只验；维护者执行准入才写该槽库、`SHA256SUMS`、`provenance.json` 和 manifest。Linux 把 `linux_baseline_candidate` 转成 `linux_baseline` 并留下独立证明。 |
| 最终 wheel | `wheels.yml` 从已提交库各槽打包一次、`--inspect-wheel` 生成 wheel SHA 和 native inventory；CPython 3.10/3.14 用同一件 artifact 安装，清理库路径覆盖，逐日志核查身份和协议。Linux 还在原生 Debian 11 环境双端安装同一 wheel；Windows 另在同机比较实际成品、原始 PyPI 0.11.0、旧 fork 0.9.2 与新采官方 Firefox 161。 | 失败时日志仍可上传；`verified-ruyihttp-<slot>-<run>-<attempt>` 只在成功后上传，发布方核对后另行交付。 |

### Linux：`GLIBC_2.30` 是符号上限，2.31 是验收与标签

两槽记录的最高动态 `GLIBC` 需求均为 **2.30**；真实的验收用户态为 **Debian 11 / glibc 2.31**，因此 wheel 为 `manylinux_2_31_*`。预检查看的是 version needs，不是 ELF 导出了什么，也要检查 Bullseye 的 C++、GCC 等边界（`GLIBCXX_3.4.28`、`CXXABI_1.3.12`、`GCC_7.0.0` 上限），以及 runtime loader 实际解析到何处。最高符号不构成 2.30 上的 pip 标签、依赖解析、C++ 提供者或运行时证明。旧库保留 `manylinux_2_39_*` 或更窄的发布标记；`RUYIHTTP_GLIBC=2.31`、手改文件名或 `WHEEL/Tag` 均不能把旧库转成已实测低基线。`setup.py` 交叉检查同一份构建/ELF/准入记录，显式候选例外只对已测量、已打诊断版本戳且启用 `RUYIHTTP_BUILD_BASELINE_CANDIDATE=1` 的构建生效。[两槽 manifest](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ruyihttp/runtime-manifest.json#L85-L188) · [策略交叉校验](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/tools/linux_baseline.py#L149-L206) · [打包守卫](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/setup.py#L63-L95)。

## 5. Firefox 对照：直接采集、稳定投影和用途边界

对照是同 OS、同原生 CPU 的 **Mozilla 官方 en-US Firefox 159.0、160.0、161.0**。采集用带签名的 `SHA256SUMS` 验归档，锁签名钥匙、归档摘要、可执行文件、BuildID、源码戳；使用独立临时用户资料、只给 localhost 测试 CA，隔离外网（Linux netns、macOS PF、Windows 程序级防火墙）。官方参考至少两次冷样本／版本／槽：H1/H2 为顶层导航；H3 为 `/boot` 取得 `Alt-Svc` 后的普通同源 `fetch('/profile-wire')`，仅 UDP 成功，官方 TCP 监听留下 bootstrap／验证但对目标路径回 503，wheel fixture 在 bootstrap 后关闭目标 TCP 路线。采集的是 origin 观察，而非库自报。从 [signed acquisition](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_reference_releases.py#L120-L159)、[浏览器采集](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_reference_capture.py#L340-L399) 到 [产物准入](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_reference_admit.py#L37-L97)，将原始 ZIP/成员 SHA-256 拴在实际 run/job 上：[官方五槽回执](../firefox-reference-collection.md#admitted-observations)；wheel 先校验固定参考身份再比较。

比较器保留请求目标、ALPN、完整 UA、有序伪头/普通头、TCP ClientHello 稳定字段、有序 H2/H3 SETTINGS、QUIC 首个 Initial 版本与协商版本（实测 **v1 Initial，v2 协商**）、选定 transport parameters 等。只映射回环已知 ephemeral port，`Referer` 保留具体 `/boot` 路径；原始观测保留 ClientHello 扩展顺序，只有官方同槽/版本/上下文本身出现排列变动才投影为成员和 GREASE 数目、仍保留可证实的固定位置。若稳定扩展确实洗牌，wheel 最多五组新鲜连接要出现至少两种合规排列且每组固定字段都过。Initial 记录 CID/token 长度及包号宽度；投影处理包长的 DCID/包号宽度差异，不以随机 CID、密钥或包号值比全包。H2 独立首航门禁还测连接 WINDOW_UPDATE、独立 PRIORITY 序列、首请求 stream 与内联依赖/权重；SETTINGS ACK 相对时序记录、但不要求固定。[稳定投影](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_wire.py#L128-L304) · [重采证据](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_wire.py#L324-L412) · [H2 首航投影](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/firefox_h2_preface.py#L133-L163)。

**对照结论只覆盖这些请求上下文与选定字段。** Windows 同机控制独立安装三个 Python wheel 并保留与 Firefox 的差异，门禁针对候选对官方，而非候选对上游。旧 `ci/firefox_wire_reference.json` 历史 Linux ARM64 H3 场景与新 Fetch 场景不等价，不能充当当前槽证据。随机加密材料、真实站点行为、浏览器全部功能、任意负载时序和 MASQUE 外层代理 hop 均在对照范围之外；亦未把 159/160/161 实测推广成 100–158 的覆盖证明。[Windows comparator](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/compare_windows_wire.py#L88-L127) · [三方采样](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/compare_windows_wire.py#L128-L249) · [采集场景与历史负对照](../firefox-profile-wire.md)。

| 换供体或改补丁 | 在 `tools/posix_firefox161.py` 更新核实过的 gitlink/Firefox/vendor/policy pin 和精确补丁序列；重新产出 `source.json`、`standalone-lock.json`、`preflight.txt` 和原生证据。按内容变动重测 POSIX QUIC 策略、owner thread/短写/二进制和 JSON、IPv4/IPv6 H3、证书负对照；如改变采集上下文，重新采真实官方参考及其签名 ZIP/run，不能手改基准消除差异。 | `git apply --check` 失败先比供体 SHA 和上游文件；`Unexpected source patch names, order or bytes` 比 provenance 的有序摘要；`Invalid HTTP/3 body …` 对照 ctypes 类型、owner、fin/count；`firefox-profile-wire.jsonl` 先区分 bootstrap／Fetch／ALPN，再看差异路径与 repeat proof。 |
| 更新 CA、cutoff 或 PSL | 更新并审核 `docs/upstream-0.11.0-data.json` 的输入/规范化摘要；`python -B tools/sync_trust_data.py --wheel "$D_WHEEL" --certdata "$CERTDATA" --psl "$PSL"` 先只验证，确认差异后在工作分支加 `--apply` 写三份数据及 manifest；跑 `tests/test_upstream_trust_data.py`、`tests/test_cookie_site.py`、`tests/test_trust_and_buffers.py` 及实装轮的 `ci/smoke_trust_rotation.py`。开新握手观察替换，若要淘汰已建 TLS 则关闭旧会话。 | `outdated` 对照 LF 与三份数据清单散列；锚变化用 `ci/verify_trust_transition.py` 从确切旧 wheel 取三张移除根、固定时间验证，并保留 `ISRG Root X1` 正样本。锚成员测试不是站点证书撤销验证。 |
| 下调 Linux 标签遇阻 | 先在目标原生 CPU 的 `baseline` job 构建；保留原 ZIP、构建/ELF 收据、`auditwheel` 结果及普通 pip 的独立最低用户态证明；`promote_native_candidate.py … --check-only` 对照实际构建与实装，再按准入流程提交 bank。发布时重新跑最终 wheel 双端门禁。 | `measured but unadmitted` 是暂存候选当正式包；`ELF receipts differ` 查目标库字节或 `readelf --version-info` 的 needs 与 `DT_NEEDED` 闭包；旧 wheel 应只在 Bullseye 因“不支持平台”失败，在现代环境却须能升级；`both-endpoints.json` 缺失则逐查 `summary.json`、原 wheel 摘要、`masque-wire.json`。 |

常用复核命令（先设置 `SLOT`、`WHEEL` 为目标槽与确切 wheel 的绝对路径；在对应原生主机操作）：

```bash
# 仓库根目录：静态 bank、ABI 和单包无加载检查（verify_runtime 需要 lief）
python -B tools/build_native.py --check
python -B tools/verify_runtime.py
python -B tools/build_native.py --inspect-wheel "$WHEEL" --platform "$SLOT"
python -m unittest discover -s tests -p 'test_native_deployment.py' -v
python -m unittest discover -s tests -p 'test_build_native_wheel.py' -v
python -m unittest discover -s tests -p 'test_linux_candidate.py' -v
python -m unittest discover -s tests -p 'test_glibc231_qualification.py' -v

# 严格验证某个已装轮：干净 venv、从源码目录外运行（macOS/Linux Bash）
ROOT=$(pwd -P)
STATE=$(mktemp -d)
python -m venv "$STATE/venv"
PY="$STATE/venv/bin/python"
cd "$STATE"
unset NECKO_CORE_LIBRARY NECKO_QUIC_LIBRARY NECKO_FIREFOX RUYIHTTP_PLATFORM RUYIHTTP_MACHINE PYTHONPATH LD_LIBRARY_PATH DYLD_LIBRARY_PATH DYLD_FALLBACK_LIBRARY_PATH
"$PY" -m pip install "${WHEEL}[masque,socks]" 'aioquic==1.3.0'
"$PY" -I "$ROOT/ci/verify_installed.py" "$SLOT" "$WHEEL"
"$PY" -I "$ROOT/ci/smoke_native_target.py" "$SLOT"
"$PY" -I "$ROOT/ci/smoke_firefox_profiles.py" "$SLOT" --output wire.jsonl
"$PY" -I "$ROOT/ci/verify_h2_first_flight.py" "$SLOT" wire.jsonl h2-first-flight.json
RUYIHTTP_TEST_NATIVE_H3=1 RUYIHTTP_REQUIRE_H3_IPV6=1 RUYIHTTP_REQUIRE_H3_BODY_ABI=1 \
  "$PY" -I -m unittest discover -s "$ROOT/tests" -p 'test_h3_body_abi.py' -v
"$PY" -I "$ROOT/ci/smoke_masque.py" --json-output masque-wire.json
```

最后一组的 `RUYIHTTP_REQUIRE_H3_BODY_ABI=1` 给四个 POSIX bank；Windows 在 Bash 中改用 venv 下的 `Scripts/python.exe`，运行该测试时去掉这个变量。完整 gate 顺序与跳过条件以 [qualify_wheel](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/ci/qualify_wheel.py#L15-L103) 为准：包括 `test_firefox_wire_gate.py`、`test_http3_native.py`、`test_alt_svc_native.py`、POSIX QUIC 策略、`smoke_proxy_chain.py`、H2 EOF、请求边界、MASQUE RFC 9298 与固定 Go peer。要提交 Linux baseline 的**只读准入**申请，给 `tools/promote_native_candidate.py <slot> <wheel> <evidence-dir> <run.json> <jobs.json> <artifacts.json> --check-only` 再带 `--native-evidence-zip`、`--native-wheel-zip`、`--floor-run`、`--floor-jobs`、`--floor-artifacts`、`--floor-cp310-zip`、`--floor-cp314-zip` 七项；保存原始 API 回应与 ZIP，切勿只留终端成功截图。[参数](https://github.com/Facetomyself/ruyihttp/blob/9e88bfe023fd46a96254f8de66e8d72517339911/tools/promote_native_candidate.py#L284-L296) · [更完整的编译准备](../build-native.md) · [最低系统操作说明](../linux-glibc231-qualification.md)。
